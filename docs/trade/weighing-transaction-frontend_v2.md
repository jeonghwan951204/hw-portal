# 계근 거래 프론트엔드 구현 요청

> 상태: V48 기준, 미배정 계근 선택 등록 및 결제 완료로 거래 마감
> 작성일: 2026-10-12  
> 백엔드 설계: [계근 기반 거래 도메인 설계](weighing-transaction-design.md)

거래 화면은 수집한 계근 데이터를 빠짐없이, 실무자가 익숙한 거래 형태로 확인하고 정리할 수
있어야 한다. 거래처·품목이 매핑되지 않은 계근도 거래 목록과 상세에 반드시 나타나며, 매핑상태는
노출 여부가 아니라 표시 방식과 후속 정리 대상을 결정한다.

## 1. 화면의 데이터 구조

프론트엔드는 거래 헤더와 거래 생성 유형에 따른 상세 구조를 사용한다.

```text
transaction
  ├─ 거래·결제 정보
  ├─ WEIGHING: weighingRecords[]
  │    └─ 계근 원본·차량·품목·중량·단가·금액 정보
  └─ MANUAL: manualItems[]
       └─ 직접 입력한 차량·품목·중량·단가·금액 정보
```

별도의 차량 운행 ID나 화면은 사용하지 않는다. 한 거래에 여러 차량이 포함될 수 있으며, 같은
차량번호의 계근은 화면에서 그룹으로 묶어 읽기 쉽게 보여준다.

수기 거래에는 계근 원본을 나중에 추가하지 않는다. 계근 거래와 수기 거래는 서로 다른 유형으로
표시하고 한 거래 안에서 두 상세 유형을 섞지 않는다.

## 2. 누락 없는 표시 원칙

계근은 동기화 후 미배정 상태로 대기하며, 실무자가 선택해 등록한 계근만 거래 목록에 포함된다.
다음 상태도 미배정 목록과 등록된 거래 상세에서 제외하지 않는다.

- 거래처 또는 품목 미매핑
- 매핑 후보가 여러 개인 상태
- 원본 거래처명 또는 품목명이 없는 상태
- 거래구분을 해석하지 못한 상태
- 자동 연결 후보가 없거나 여러 개인 상태

표시 방법은 다음과 같다.

| 데이터 상태 | 화면 표시 |
|---|---|
| 내부 매핑 성공 | 내부 정식명 |
| 미매핑 또는 모호 | 원본명과 `미매핑` 또는 `확인 필요` 배지 |
| 원본명 없음 | `거래처 미입력` 또는 `품목 미입력` |
| 거래구분 해석 실패 | `구분 확인 필요` |
| 거래 미배정 | 거래 등록의 계근 선택 목록에 표시 |

미매핑 계근을 기본 조회에서 숨기지 않는다. 거래 합계도 미매핑 계근을 포함하며,
정리가 필요한 거래는 경고 필터로 조회한다.

## 3. 거래 목록

### 검색 조건

- 거래일 시작일과 종료일: `dateFrom`, `dateTo`
- 거래처 선택: `companyId` (거래처 검색·선택 후 ID 전달)
- 자사: `ownerCompany`
- 거래구분: `tradeDirection` (`PURCHASE`, `SALE`, `UNKNOWN`)
- 결제상태: `paymentStatus` (`UNPAID`, `VAT_PAID`, `PAID`)
- 경고: `hasWarning` (생략=전체, true=경고 있음, false=경고 없음)

경고는 거래처 미매핑, 품목 미매핑, 적용 단가 누락, 묶음 경고, 거래구분 UNKNOWN,
포함 계근 원본 삭제 중 하나라도 있는 경우다. 목록과 상세의 `hasWarning`도 같은 기준이다.
이 필터는 페이징 전에 적용되며 전체 건수에도 반영된다. `MERGED` 거래는 검색에서 제외한다.
거래 생성 유형·확인상태·별도 거래상태·자유 검색어 필터는 사용하지 않는다.

차량번호는 목록과 상세의 표시값이며 거래 조회 필터에는 포함하지 않는다.

```text
GET /api/weighing-transactions?dateFrom=2026-10-01&dateTo=2026-10-31&companyId=1&ownerCompany=HOJAE&tradeDirection=PURCHASE&paymentStatus=UNPAID&hasWarning=true&page=1&size=20
```

### 목록 표시값

- 거래일
- 계근·수기 배지
- 자사
- 거래처명과 매핑상태
- 입고·출고·구분 확인 필요
- 차량 대수와 차량번호 요약
- 품목 수와 품목명 요약
- 계근 건수
- 총 실중량·인수량·감량
- 표시금액과 금액 상태
- 결제상태와 결제금액
- 진행 중·마감·합쳐짐 상태
- 자동 묶음 경고와 비고 존재 여부

`MERGED` 거래는 목록에서 제외한다. 미매핑 데이터는 기본 목록에서 제외하지 않는다.

## 4. 거래 상세

### 거래 공통 정보

- 거래 ID와 버전
- 거래일
- 자사
- 거래처와 매핑상태
- 입고·출고·구분 확인 필요
- 통화
- 결제상태와 결제금액
- 진행 중·마감·합쳐짐 상태
- 비고
- 생성일과 최근 수정일
- 생성 유형: 계근 또는 수기

진행 중 거래는 내용을 편집할 수 있다. 결제 완료로 마감된 거래는 결제정보 외 입력을 읽기 전용으로 표시한다.

### 수기 거래 생성과 상세

거래 목록에 `수기 거래 등록` 버튼을 제공한다. 등록 화면에서 거래일, 자사, 거래처, 입출고 구분,
통화, 비고와 한 개 이상의 품목을 직접 입력한다. 품목 행에는 차량번호, 품목, 실중량, 인수량,
감량, kg당 적용 단가, 실제출고량과 품목 비고를 입력할 수 있다.

내부 품목을 선택하지 않아도 품목명을 직접 입력해 저장할 수 있다. 결제 완료 전에는 품목을 추가·수정·
제거할 수 있고 마감 후에는 읽기 전용으로 표시한다. 수기 거래 상세에는 계근 원본 비교 영역이나
계근 추가 기능을 표시하지 않는다.

### 포함 계근 목록

계량일자, 이차시간, 일차시간, 일자별 순번과 계근 ID를 이용해 안정적으로 정렬한다. 같은 차량의
연속 계근은 그룹 머리글이나 배경으로 구분하되 개별 계근을 생략하지 않는다.

각 계근 행에는 다음 값을 표시한다.

- 계량일자와 차량번호
- 일차·이차 중량과 시각
- 거래처 원본명과 매핑 결과
- 품목 원본명과 매핑 결과
- 실중량·인수량·감량
- kg당 원본 단가와 거래 적용 단가
- 계근 원본 금액
- 예상금액
- 실제출고량
- 실제금액
- 최종 표시금액
- 자동·수동 배정 여부와 묶음 경고

실무자가 계근 원본과 정리된 거래값을 비교할 수 있도록 원본명·원본 단가·원본 금액을 숨기지
않는다. 매출 계근의 원본 단가가 비어 있으면 `미입력`으로 표시하고 적용 단가 입력란을 제공한다.

## 5. 거래 편집과 결제 마감

별도의 거래 확인·확인 취소 버튼과 API는 제공하지 않는다. 미결제·부가세 결제 거래는 편집할 수
있으며, `PAID`로 저장하면 마감된다. 마감할 때 계근·품목·중량·단가·금액을 스냅샷으로 고정한다.
마감된 거래는 결제정보 외 읽기 전용이다.

결제 완료 전에는 거래구분이 정해져 있어야 하고, 출고는 모든 행의 적용 단가, 입고는 모든 행의
인수량이 필요하다. 미매핑 거래처·품목은 경고로 표시하되 마감을 차단하지 않는다.
`amountStatus=CONFIRMED`는 실제출고량 입력에 따른 금액 상태이며 별도의 거래 확인 상태가 아니다.

## 6. 적용 단가와 출고 실제출고량

진행 중 거래의 계근 행에서 kg당 적용 단가를 수정할 수 있다. 원본 단가가 있다면 최초 적용
단가로 보여주고, 매출 원본 단가가 없다면 빈 입력란으로 제공한다. 서버에 저장한 적용 단가는
계근 원본과 별도로 표시하며 계근 원본을 변경하지 않는다. 무상 출고는 빈 값 대신 0을 입력한다.

출고 거래는 상대 거래처가 인정한 실제출고량을 kg으로 입력할 수 있다.

```text
출고 예상금액 = 실중량 × 적용 단가
출고 실제금액 = 실제출고량 × 적용 단가
입고금액 = 인수량 × 적용 단가
```

입력 중 프론트 계산은 미리보기로만 사용하고 저장 후 백엔드 응답으로 교체한다. 실제출고량을
비우면 실제금액을 제거하고 예상금액을 표시한다.

| API 값 | 화면 문구 | 의미 |
|---|---|---|
| `ESTIMATED` | 예상 | 모든 품목의 실제출고량이 미입력 |
| `PARTIALLY_CONFIRMED` | 일부 확정 | 일부 품목만 실제출고량 입력 |
| `CONFIRMED` | 확정 | 모든 품목의 실제출고량 입력 |

적용 단가가 없는 계근의 금액은 `-`로 표시하고 거래 합계에서도 계산되지 않은 금액임을 구분한다.
거래 목록과 상세 응답은 `hasMissingUnitPrice`를 제공하며, 출고 거래에서 이 값이 `true`이면 결제 완료
저장을 차단하고 누락된 단가를 입력하도록 안내한다.

적용 단가와 실제출고량은 계근 행 단위 API로 함께 또는 각각 저장한다.

```json
{
  "version": 3,
  "appliedUnitPrice": 12500,
  "actualDeliveryWeightKg": null
}
```

`appliedUnitPrice`는 kg당 단가이며 결제 완료 전에는 수정하거나 NULL로 지울 수 있다. 결제 완료 요청
시점에는 출고 거래의 모든 행에 값이 있어야 한다.

## 7. 계근 이동과 거래 분리

실무자는 잘못 묶였다고 판단한 계근을 선택해 다음 작업을 할 수 있다.

- 다른 진행 중 거래로 이동
- 선택 계근으로 새 거래 생성
- 같은 차량번호의 계근 전체를 한 번에 선택

수동 이동과 분리 사유는 선택 사항이다. 사유가 없어도 실무자의 명시적인 선택을 신뢰해 처리하고
작업자, 이동 전후 거래, 대상 계근과 처리시각은 항상 이력으로 남긴다.

결제 완료 거래에서는 계근을 이동·분리하거나 거래를 합칠 수 없다. 결제상태를 정정해 OPEN으로
돌아온 거래는 다시 편집할 수 있다.

## 8. 거래 합치기

1. 거래 목록에서 진행 중 거래를 두 건 이상 선택한다.
2. `거래 합치기`를 누른다.
3. 대상 거래와 이동할 계근을 확인한다.
4. 필요한 경우 합치기 메모를 입력한다.
5. 성공 후 대상 거래 상세로 이동한다.

자사, 거래처, 거래구분과 통화가 같은 거래를 기본 대상으로 한다. 미매핑 원본명이 다르면 경고를
표시하되 실무자가 같은 거래처라고 판단해 명시적으로 선택한 경우 처리할 수 있다. 합치기 메모는
선택 사항이다.

합쳐져 비게 된 거래는 삭제하지 않고 `MERGED` 상태로 보존한다. 해당 상세에서는 대상 거래
링크와 합치기 이력을 표시한다.

## 9. 결제와 마감

거래 단위로 다음 값을 입력한다.

- `UNPAID`: 미결제, 진행 중
- `VAT_PAID`: 부가세 결제, 진행 중
- `PAID`: 결제 완료, 마감
- 결제금액

`VAT_PAID`는 실무자가 판단해 선택하며 프론트는 부가세 금액을 자동 계산하거나 결제금액으로
상태를 추론하지 않는다.

별도의 `거래 마감` 버튼은 제공하지 않는다. 결제상태를 `PAID`로 저장하면 백엔드 응답에서 거래가
즉시 마감상태로 바뀐다. 별도 거래 확인 없이 `PAID`를 선택해 저장한다.

결제정보가 잘못된 경우 상태와 금액을 다시 수정할 수 있다. `PAID`를 다른 상태로 바꾸면 마감
표시와 계근 스냅샷 고정을 해제하고 거래 구성을 다시 편집할 수 있다. 별도의 거래 재개
버튼과 삭제 기능은 제공하지 않는다.

## 10. 경고와 운영 확인

거래 등록의 기본 화면은 거래에 묶이지 않은 계근 선택 목록이다. 날짜·자사·입출고·차량번호·
거래처명으로 검색하고 여러 건을 선택한 뒤 등록한다. 신규 동기화 계근은 기존 거래에 자동으로
추가되지 않는다. 다음 항목은 계근 선택 및 거래 상세에서 확인할 수 있어야 한다.

- 거래처·품목 미매핑 또는 복수 후보
- 거래처명·품목명 미입력
- 거래구분 해석 실패
- 자동 연결 후보 모호성
- 마감 후 원본 변경 감지
- 출고 실제출고량 일부 미입력

관리자용 정합성 화면이나 점검 API에서는 다음 값을 확인할 수 있어야 한다.

```text
전체 계근 원본 수
거래에 포함된 고유 계근 수
거래 소속이 없는 계근 수
두 거래 이상에 중복된 계근 수
```

소속 없는 계근은 등록 대기 중인 정상 상태다. 중복 배정, 매핑 누락과 빈 거래는 정합성 오류다.

## 11. 요청할 API

경로와 DTO 이름은 백엔드 구현 시 조정할 수 있으나 다음 기능이 필요하다.

| Method | 경로 예시 | 용도 |
|---|---|---|
| `GET` | `/api/weighing-transactions` | 모든 매핑상태를 포함한 거래 목록·검색·페이징 |
| `GET` | `/api/weighing-transactions/unassigned-weighing-records` | 거래 등록용 미배정 계근 검색·페이징 |
| `POST` | `/api/weighing-transactions` | 선택한 미배정 계근으로 새 거래 등록 |
| `GET` | `/api/weighing-transactions/{id}` | 포함 계근과 거래 상세 조회 |
| `POST` | `/api/weighing-transactions/manual` | 수기 거래와 최초 품목들을 함께 생성 |
| `PATCH` | `/api/weighing-transactions/{id}` | 결제 완료 전 거래정보 수정 |
| `POST` | `/api/weighing-transactions/{id}/manual-items` | 결제 완료 전 수기 품목 추가 |
| `PATCH` | `/api/weighing-transactions/{id}/manual-items/{itemId}` | 결제 완료 전 수기 품목 수정 |
| `DELETE` | `/api/weighing-transactions/{id}/manual-items/{itemId}` | 결제 완료 전 수기 품목 제거 |
| `POST` | `/api/weighing-transactions/merge` | 여러 진행 중 거래 합치기 |
| `POST` | `/api/weighing-transactions/{id}/split` | 선택 계근을 새 거래로 분리 |
| `POST` | `/api/weighing-transactions/{id}/move-records` | 선택 계근을 다른 거래로 이동 |
| `PATCH` | `/api/weighing-transactions/{id}/weighing-records/{mappingId}` | 서버 적용 단가·실제출고량 수정 |
| `PATCH` | `/api/weighing-transactions/{id}/payment` | 결제정보 수정과 `PAID` 마감 반영 |
| `GET` | `/api/weighing-transactions/{id}/history` | 거래 변경 이력 조회 |
| `GET` | `/api/weighing-transactions/integrity` | 계근 누락·중복 정합성 점검 |
| `POST` | `/api/admin/weighing-transactions/migration/run` | 과거 데이터 자동 묶기용 관리자 배치, 일반 운영에서는 호출하지 않음 |

별도의 마감 API는 제공하지 않는다.

### 기본 거래 등록 흐름

1. `GET /api/weighing-transactions/unassigned-weighing-records?page=1&size=20`으로 선택 목록을 조회한다.
   기존 계근 조회의 날짜·자사·입출고·차량번호·원본 거래처명 필터를 그대로 지원한다.
2. 선택한 `weighingRecordId`들을 아래 요청으로 등록한다.
3. 응답의 거래 상세로 이동해 거래처·거래일·단가를 수정하고, 결제 완료 시 PAID로 저장한다.

```json
{
  "weighingRecordIds": [101, 102, 103],
  "allowCounterpartyMismatch": false,
  "memo": "실무자 선택 등록"
}
```

한 번에 1~1000건을 선택할 수 있다. 이미 배정되었거나 원본 삭제된 계근을 포함하면 전체 등록이
실패한다. 자사·입출고 구분·통화가 같은 계근만 등록 가능하며 차량과 품목은 달라도 된다.
거래처가 다르면 사용자에게 확인을 받은 경우에만 `allowCounterpartyMismatch=true`를 전달한다.
거래처는 계근일·계근시각·일련번호·ID 순 첫 계근에서 가져오고 거래일은 선택 계근의 가장 최근
계근일로 설정한다. 매핑되지 않은 거래처·품목도 등록할 수 있다.
`UNKNOWN` 계근도 같은 구분끼리 등록할 수 있으나 결제 완료 전에 거래구분을 수정해야 한다.

충돌 응답(409)이면 선택 목록을 새로 조회한다. 등록 성공 후 해당 계근은 미배정 목록에서 빠진다.
계근 없이 직접 입력하는 기능은 기존 `/manual` API를 사용하며 기본 등록 동작과 별도로 제공한다.

## 12. 프론트 검증과 서버 검증

프론트는 빠른 피드백을 위해 다음 조건을 먼저 검사한다.

- 적용 단가, 실제출고량과 결제금액은 0 이상
- 출고 거래 마감 시 모든 계근의 적용 단가 입력 필수
- 수기 거래는 품목 한 건 이상 필수이며 계근 목록을 받을 수 없음
- 계근 거래와 수기 거래는 서로 합치기 불가
- 마감된 거래에서는 결제정보 외 수정 기능 비활성화
- `PAID`는 별도 확인 절차 없이 저장하며 저장과 동시에 마감
- 요청에는 최신 `version` 포함

수동 이동·분리·합치기의 사유 입력 여부는 검증하지 않는다. 동일한 업무 조건은
백엔드에서도 검증하며 최신 상태와 금액은 서버 응답을 최종값으로 사용한다.

## 13. 구현 순서

1. 미배정 계근 조회·선택 및 새 거래 등록
2. 누락 없는 거래 목록과 상세 조회
3. 미매핑·확인 필요 표시와 계근 원본 비교
4. 결제 완료 시 마감과 스냅샷 고정
5. 적용 단가와 출고 실제출고량 입력
6. 계근 이동·분리와 여러 거래 합치기
7. 결제정보 저장과 `PAID` 자동 마감
8. 계근 누락·중복 정합성 점검

기존에 배정된 거래는 유지한다. 이후 신규 계근은 미배정 상태로 대기하므로 전환 배치 실행 없이
실무자가 필요한 계근을 선택해 등록한다.
